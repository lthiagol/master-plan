LONG-ROAD HANDOFF
================

What is "the long road"?
------------------------
After the M100-M103 chain (lifecycle, findings, multi-lane path, raul path
CLI) and the M125 work (path graph, blocked lane), the dogfood plan has
two long-horizon milestone chains sitting at lifecycle=approved. These
are the "long road" — multiple days of execution-mode work before
another M100-M125-sized feature lands.

The two chains, in order of dependency:
  C.  110 -> 111 -> 112 -> 113 -> 114 -> 115 -> 116 -> 117 -> 118
        (hygiene, fragment-CLI, read, write-safety, test-sweep,
         TUI polish, meta, verifier, dogfood close-out)
  D.  119 -> 120 -> 121, 122 -> 123
        (agent role dispatch, mp-flow, mp-coordinator, mp-runner, mp-handoff)

The chains are independent. Pick one based on what's more pressing.

Order of execution
-----------------
  1. B-67   (1-2 days, low risk; clears 11 dirty milestones)
  2. M124   (decompose + execute, 3-4 days; closes 8 prior review ERs)
  3. B-68   (1-2 hours; just-groom-the-existing-work)
  4. Long road — pick one:
       a. M110-M118 (hygiene + dogfooding infrastructure; 9 milestones)
       b. M119-M123 (agent skill system; 5 milestones)

Recommendation: B-67, then M124, then B-68, then the long road.

Why that order
--------------
B-67 is the highest-leverage-per-unit-effort work in the plan. Without
it, every state mutation after the M100 bulk migration reintroduces the
11 dirty milestones, and M124's AC-01 doesn't land cleanly.

If the long road starts with M110 (hygiene), the chain delivers 9
incremental milestones with the M118 "dogfood backlog close-out" as
the self-referential payoff. Pure process work.

If the long road starts with M119 (agent role dispatch), the chain
delivers the role-dispatch / mp-flow / coordinator / runner / handoff
skill system. Strategic for the team's dogfooding workflow but doesn't
address the 11 dirty milestones, doesn't close prior review findings,
and doesn't fix M100 ER-1.

What to do if you're picking this up
------------------------------------
1. Read the milestone path recommendation note at
   `~/ai-notes/projects/personal/master-plan/2026-07-06-next-milestone-paths-recommendation.md`
   for the full effort / complexity / gains comparison.
2. Confirm execution mode (`mp execution status`).
3. Start with B-67 unless something has changed in the dogfood plan
   (run `mp validate` and `mp status --summary` to verify state).
4. After B-67, run the bulk migration a second time — it should be a
   no-op (idempotent). Confirm 0 dirty milestones.
5. Decompose M124, execute, run review.
6. Then choose the long road (M110-M118 or M119-M123) and start
   executing in order.

What NOT to do
--------------
- Don't do M119 first. The 5-milestone chain looks like a quick win
  but it's strategic infrastructure, not urgent cleanup.
- Don't merge refactor branches that contain undone setter fixes; the
  B-67 work is the load-bearing piece.
- Don't file the long-road work as a single mp milestone; the
  dependencies between the 9 (or 5) child milestones are real and
  matter for execution-mode handoff.
