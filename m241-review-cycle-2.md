The new `the_takeover_row_cycle_count_comes_from_the_cycle_history` test asserts exact per-row cycles (M240=3, M241=1, M242=2) and pins "at least one row has `cycle > 1`" so a hard-coded 1 cannot pass the test by accident. Test count went 20 → 24 in `autopilot_while_executing`. The fix is real and correct for every multi-milestone run.

- F-02 (medium, spec-drift): the F-01 fix is correct for the multi-milestone case but does not cover single-milestone sessions — a documented gap the runner disclosed honestly in `queued_milestones'` doc comment (`crates/raul/src/tui/autopilot/setup.rs:627-641`). The root cause is the pre-existing gate at `crates/raul/src/tui/autopilot.rs:1792`: `if queue.rows.len() > 1 { Some(queue) } else { None }`. A 1-milestone session therefore sets `app.queue_view = None`, `queued_milestones` falls into the `setup.selected` branch, and `TakeoverRow.cycle` becomes `queue_row_default_cycle() = 1` even when `session.queue_cycle_history[]` says the milestone is on cycle 3. The spec scope statement requires "one row per queued milestone (id, lifecycle, cycle count, lifecycle-position bar)" without qualifying on session size; a 1-row queue is a real, if uncommon, case (a drive that started with a single milestone), and the data is already in the payload. The fix is a one-line change in `refresh_from_json` — change `> 1` to `> 0` (or drop the gate entirely and let `view.rows.is_empty()` decide). The runner chose scope restraint ("a change to typed-row code outside the takeover's row builder") and the doc comment, but the spec lists cycle count as a required row component rather than a best-effort one, so a documented gap is not equivalent to a met requirement. MEDIUM, not HIGH, because the typical takeover use case is multi-milestone (a single-milestone run does not need a full takeover dashboard) and the value is functionally a 1-vs-3 difference rather than a wrong value; not LOW because the spec names the field and the data is reachable. If accepted, the runner's doc comment is the right artifact to keep alongside the fix.
