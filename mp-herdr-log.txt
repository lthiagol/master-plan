### Headline lessons still load-bearing (R1-R15 condensed)

1. **Lane notifications** must be `herdr agent prompt <ORCH_PANE_ID> "..."` as
   a *shell command*, not printed prose. (R4)
2. **Per-AC evidence** must be `<cmd> exit <code> (<X>/<Y> pass)` — generic
   strings fail validation. (R10)
3. **Orchestrator must verify state independently** before accepting a lane's
   "done" notification:
   `state = mp show milestone <id> --fields milestone.lifecycle,milestone.execution_status`.
   `assert state.lifecycle in {executed, complete}; assert state.execution_status == "done";`
   `assert len(activity entries for <id>) > 0`. If any check fails: REJECT and
   send back. (R5)
4. **Per-step discipline** — runner MUST call `mp milestone step done <id>
   <step>` for every step. Skipping breaks the audit trail and the
   orchestrator's verification. (R6)
5. **`make clean` before each reviewer cycle** that involves validation —
   removes 28.8 GiB of stale cargo artifacts in ~30s; ensures cold build is
   truly cold. (R9)
6. **Role boundaries** must be encoded at multiple layers (skill content
   + opencode permission config + orchestrator verification), because
   prompt-only enforcement has failed in practice (M203). (R-late)
7. **Commit strategy** for the runner contract: 1 commit per step, 1 commit
   per finding (never grouped), 1 lifecycle-evidence meta-commit per cycle,
   per-AC evidence via `mp milestone criterion pass` (NOT generic commits). (R-late)
